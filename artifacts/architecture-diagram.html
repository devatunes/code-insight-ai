Code Insight AI — infraestructura en AWS

Qué hace cada componente, y por qué ese y no otro

Cliente (navegador)

Sirve para: es quien abre la app — no es parte de AWS, es el punto de partida del diagrama.

CloudFront

Qué es: la CDN de AWS — una red global de puntos de presencia (edge locations) que cachea y sirve contenido cerca de cada usuario.

Sirve para: sirve el frontend estático desde el borde (rápido en cualquier parte del mundo) y, en la misma distribución, hace de proxy hacia el backend en /api/*.

Por qué éste: frontend y backend quedan en un solo dominio, sin CORS real y sin exponer el ALB con su propio HTTPS. Alternativa descartada: dominios separados con CORS configurado — fricción sin ningún beneficio real acá.

Seguridad: termina TLS/HTTPS de cara al usuario y esconde la topología real del backend (VPC, ALB, tasks) detrás de un solo dominio público.

S3

Qué es: el almacenamiento de objetos de AWS (Simple Storage Service) — guarda archivos como objetos direccionables por clave, no como un disco tradicional.

Sirve para: guarda los archivos ya compilados del frontend Angular (HTML/JS/CSS).

Por qué éste: es el origin que CloudFront sabe servir de forma nativa, a costo marginal. Alternativa descartada: servir el build desde el propio backend — mezcla dos responsabilidades distintas y pierde el cacheo global.

Seguridad: el bucket es completamente privado (todo acceso público bloqueado); solo CloudFront puede leerlo, vía Origin Access Control y una política que exige que la request venga de esa distribución.

VPC privada

Qué es: una red aislada dentro de AWS (Virtual Private Cloud) — quien la crea define sus propios rangos de IP, subredes y reglas de tráfico, como si fuera un datacenter propio.

Sirve para: aísla toda la red del backend de internet — nada adentro tiene IP pública salvo el ALB.

Por qué éste: es la práctica correcta por defecto, no algo que se "gana" solo con tráfico alto. Alternativa descartada: sin VPC (lo que hacía la kata anterior) — ahorra el costo de los endpoints, pero deja la base de datos expuesta.

Seguridad: aislamiento de red — nada dentro de la VPC tiene ruta hacia o desde internet salvo lo explícitamente permitido (ALB de entrada, NAT de salida).

ALB

Qué es: un balanceador de carga de capa 7 (Application Load Balancer) — reparte tráfico HTTP/HTTPS entre varias tasks según reglas y health-checks, no solo por IP/puerto.

Sirve para: recibe el tráfico que le reenvía CloudFront y lo reparte a las tasks de ECS Fargate.

Por qué éste: su Security Group solo acepta la lista administrada de IPs de CloudFront, no cualquier IP de internet. Alternativa descartada: exponer el backend directo, sin balanceador ni health-checks.

Seguridad: el Security Group solo permite entrada desde la prefix list administrada por AWS de CloudFront — no desde cualquier IP de internet.

NAT Gateway

Qué es: un servicio administrado de traducción de direcciones (Network Address Translation) — deja salir tráfico saliente a internet sin exponer la IP privada real del recurso que lo origina.

Sirve para: es la única puerta de salida real a internet — necesaria porque clonar un repo Git público o llamar a la API de Claude implica salir de la red privada, y no existe un VPC Endpoint para hosts arbitrarios fuera de AWS.

Por qué éste: mantiene la task sin IP pública propia. Alternativa descartada: asignarle IP pública directa a la task — la dejaría alcanzable desde internet en su propia IP, peor postura de seguridad por un ahorro menor al pensado.

Seguridad: es solo de salida — la task nunca tiene IP pública propia ni puede recibir conexiones entrantes iniciadas desde internet.

ECS Fargate

Qué es: el modo serverless de Elastic Container Service — corre contenedores sin administrar servidores ni clusters EC2 propios; AWS asigna el cómputo por task.

Sirve para: corre el contenedor del backend NestJS — clona el repo, corre la heurística, llama a Claude, guarda el historial.

Por qué éste: el trabajo tiene duración variable y necesita disco temporal real. Alternativa descartada: Lambda (como en la kata anterior) — el límite de 15 min y el /tmp efímero son un riesgo justo en la función núcleo de esta app, que clona repos de tamaño variable y puede tardar más que eso.

Seguridad: nunca ejecuta código del repositorio clonado — solo lee su estructura (nombres de archivo, carpetas, manifiestos); y su rol de IAM está acotado al mínimo privilegio (solo DynamoDB y SSM, nada más).

DynamoDB

Qué es: la base de datos NoSQL administrada de AWS — clave-valor/documento, sin servidores que aprovisionar, con escalado y latencia predecibles.

Sirve para: guarda el historial de análisis — un documento por análisis, consultable después.

Por qué éste: el dato es un documento con listas anidadas, no varias tablas relacionadas entre sí. Alternativa descartada: PostgreSQL/RDS — sería relacional solo de nombre, y cuesta una instancia corriendo 24/7 sin necesitarlo.

Seguridad: se accede solo con el rol de IAM de la task (sin credenciales embebidas) y el tráfico nunca sale a internet — viaja por el VPC Gateway Endpoint.

SSM Parameter Store

Qué es: el almacén de configuración y secretos de AWS Systems Manager — parámetros simples, con cifrado opcional vía KMS al marcarlos como SecureString.

Sirve para: guarda cifrada la API key de Anthropic.

Por qué éste: la key nunca debe estar en el código ni en el task definition en texto plano. Alternativas descartadas: variable de entorno plana en la task definition — visible para cualquiera con permiso de leerla; y Secrets Manager — rotación automática y versionado que esta app no necesita (una sola key, sin rotación programada) a cambio de un costo mensual por secreto que Parameter Store SecureString no cobra.

Seguridad: SecureString cifrado con KMS — la key nunca aparece en texto plano en el task definition ni en el código.

CloudWatch Logs

Qué es: el servicio de AWS para centralizar y consultar logs de aplicaciones e infraestructura.

Sirve para: recibe los logs del contenedor (clone, errores, análisis completado).

Por qué éste: es el destino por defecto del driver awslogs de ECS Fargate — cero infraestructura adicional que mantener para tener logs desde el día uno.

ECR

Qué es: el registro de imágenes Docker administrado por AWS (Elastic Container Registry), integrado de forma nativa con IAM.

Sirve para: guarda la imagen Docker del backend, que Fargate descarga al arrancar cada task.

Por qué éste: es el registry nativo de AWS, integrado con IAM — el rol de ejecución ya tiene permiso de descarga sin credenciales extra que gestionar.

Seguridad: escaneo automático de vulnerabilidades en cada push (scan_on_push); la descarga usa el rol de IAM de la task, sin credenciales adicionales que filtrar.

Claude API

Qué es: no es un servicio de AWS — es la API de Anthropic que expone el modelo Claude para interpretar los hechos extraídos y devolver el análisis en lenguaje natural.

Sirve para: recibe los hechos que extrajo la heurística (nunca el código fuente completo) y devuelve resumen funcional, arquitectura inferida y diagrama.

Por qué éste: es el único servicio externo, no-AWS, del diagrama — por eso el NAT Gateway existe: es la única forma de llegar hasta acá.

Seguridad: Claude solo recibe metadatos extraídos (nombres de archivo, rutas, conteos, fragmentos de manifiestos) — nunca el código fuente completo del repositorio analizado, lo que limita qué información sale de la red hacia un tercero.
